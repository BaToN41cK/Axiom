## 1. CLI для программистов — целевой образ

CLI — это контракт ядра для скриптов, CI и интеграций. Ничего интерактивного,
детерминированный вывод, машиночитаемые режимы.

### 1.0. Принципы, из которых я исхожу

1. **stdout — только данные, stderr — только человеку.** Ответ модели и
   NDJSON-события никогда не смешиваются с прогрессом, предупреждениями и
   метриками. Это уже так, и это главный принцип: любой побочный вывод в
   stdout сломает `| jq`, `| awk`, редиректы в файлы.
2. **Один вызов — один процесс, никакого состояния на диске по умолчанию.**
   Скрипт не должен «продолжать вчерашний диалог» неожиданно. Продолжение —
   только явной командой (`axiom run <session-id>`, §1.2).
3. **Коды выхода — часть API.** `0/1/2/130` уже зафиксированы (§1.1), добавление
   `124` (timeout) — единственное запланированное расширение.
4. **Всё, что умеет TUI, должно быть выразимо флагом.** Если функциональность
   нельзя вызвать из скрипта, она не считается готовой.
5. **Машиночитаемость важнее красоты.** Текстовый режим — удобный дефолт для
   человека; NDJSON — полный и стабильный для программы, включая ошибки.
6. **Никаких интерактивных промптов.** Никогда не спрашивать «продолжить?
   (y/n)» — это вешает CI. Не хватает данных → exit `2` и сообщение в stderr.
7. **Ядро — библиотека, CLI — тонкая оболочка.** Любой сценарий CLI должен
   быть воспроизводим 10 строками Python-скрипта на `ChatSession` (§1.4).

### 1.1. Текущий контракт (реализовано, менять нельзя)

```bash
axiom -p "объясни asyncio"            # ответ в stdout, прогресс в stderr
axiom --json -p "..."                 # NDJSON-поток событий ChatEvent
echo "вопрос" | axiom                 # pipe-режим
axiom --json < input.txt              # то же из файла
axiom --list-models                   # модели + capabilities (NDJSON при --json)
axiom -m gemma4:12b -p "..."          # модель на прогон
axiom -s / --no-search                # принудительный / отключённый поиск
axiom --think auto|on|off             # режим reasoning
axiom --show-reasoning                # reasoning в stderr
axiom --ollama-url http://h:11434     # удалённый Ollama
```

Коды выхода: `0` — успех, `1` — ошибка генерации, `2` — ошибка использования,
`130` — отмена (Ctrl+C / Cancelled). Всё это уже соблюдено, менять нельзя —
на них завязаны скрипты.



### 1.2. Чего не хватает (приоритет)

- [ ] **`axiom --tools`** — список зарегистрированных инструментов с их
      JSON-схемами (отладка agent loop и модели без capability `tools`).
- [ ] **`axiom --config key=value`** — разовые переопределения любых полей
      конфига (сейчас только model/search/think/url). Повторяемый флаг:
      `--config temperature=0.3 --config system_prompt="..."`.
- [ ] **`axiom --print-config`** — вывести эффективный конфиг (с учётом
      переопределений) и выйти. Нужен при отладке «почему модель так отвечает».
- [ ] **Ошибки в `--json`-потоке**: в NDJSON-режиме все ошибки должны идти
      как событие `{"type":"error",...}` в stdout-поток, а не только в
      stderr — парсинг скриптом не должен ломаться. Проверить все пути.
- [ ] **`axiom --history list|show <id>|rm <id>`** — управление историей без
      входа в TUI (история уже лежит в `~/.axiom/history/` в JSON).
- [ ] **Graceful-cancel в pipe-режиме**: SIGINT сейчас обрывает поток, не
      отправляя `cancel` в сессию.
- [ ] **`--timeout <sec>`** для поиска/чтения страниц (сейчас таймауты зашиты
      в провайдерах) и exit-код `124` по GNU-конвенции — удобно для CI.
- [ ] **`axiom run <session-id> -p "..."`** — продолжение существующего
      разговора из скрипта (сейчас скрипты всегда начинают новый диалог).

### 1.5. Сценарии, которые CLI обязан закрывать (приёмочный список)

Это то, что я буду проверять при каждом изменении CLI — если сценарий
перестал работать, релиз не готов:

```bash
# 1. Ответ в файл, прогресс человеку на экран
axiom -p "напиши changelog" > CHANGELOG.md

# 2. Пакетная обработка: много промптов, один процесс на каждый
cat prompts.txt | while read -r q; do axiom -p "$q"; done

# 3. Разбор потока событий скриптом (источники — отдельным массивом)
axiom --json -p "новости Rust" | jq -r 'select(.type=="search_result").sources[].url'

# 4. Только финальный текст (без чанков и служебных событий)
axiom --json --final -p "..." | jq -r .content          # см. §1.3

# 5. Список моделей для выбора в скрипте
axiom --json --list-models | jq -r 'select(.capabilities|index("tools")).name'

# 6. Работа с конкретной моделью и без поиска (детерминизм)
axiom -m qwen3:8b --no-search --think off -p "2+2"      # → "4"

# 7. Ошибка не ломает пайп: в NDJSON тоже есть error-событие
axiom --json --ollama-url http://127.0.0.1:1 -p "hi" | jq -r .type   # "error"

# 8. Отмена из скрипта: SIGINT → 130 и завершённый поток событий
```

- [ ] Покрыть этот список **тестом на каждый пункт** (`tests/frontends/test_cli.py`):
      сейчас покрыты базовые пути, но не пайплайны и не NDJSON-ошибки.

### 1.6. Что я сознательно НЕ буду делать в CLI

- **Свой REPL / интерактивная оболочка** — для этого есть TUI (`axiom`).
  Дублировать в CLI нельзя: сломает «никаких интерактивных промптов».
- **Псевдонимы флагов вроде `-q`, `-v`, `-j`** — конфликтуют с будущими
  флагами и создают два способа сделать одно. Только длинные читаемые имена,
  кроме уже существующих `-p/-m/-s`.
- **Конфиг через переменные окружения вместо файла** — кроме уже
  существующих `AXIOM_HOME`, `AXIOM_OLLAMA_URL`; иначе скрипты перестают
  быть переносимыми.
- **Автоматическое скачивание моделей** (`ollama pull`) — тяжёлая и
  необратимая операция из-за неявного вызова. Только явная команда
  `axiom models pull <name>` (§6 п.7).

## 3. Ядро

- [x] **Ссылки из сообщения читаются автоматически** (`agent._read_pasted_links`):
      если пользователь вставил http(s)-ссылку, агент сам вызывает `fetch_url`,
      подставляет реальный текст страницы в системный промпт (`PAGE_SYSTEM_PROMPT`)
      и публикует `search_result` с этой страницей как источником. Причина:
      `deepseek-r1:8b` возвращает `tool_calls: null` и отвечает «I cannot fetch
      live web pages» даже при переданных tools — полагаться на tool-calling
      модели нельзя (проверено живым запросом к Ollama 2026-09-18, см. тесты
      `tests/core/test_pasted_links.py`, 9 тестов).

      (`agent.OFFERED_TOOLS`) — раньше реестр его регистрировал, но модели он
      не передавался, из-за чего «открыть страницу» было невозможно в принципе.
- [x] Деталь статуса для `fetch_url` — сам URL, а не имя инструмента
      (в GUI/TUI видно, какую страницу читают).
