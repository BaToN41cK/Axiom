## 1. Скриптовый доступ к ядру (без CLI)

Ядра для скриптов и интеграций: напрямую `ChatSession`, без
промежуточного CLI-слоя. Ничего интерактивного, детерминированный вызов.

### 1.0. Принципы, из которых я исхожу

1. **stdout — только данные, stderr — только человеку.**
   (Принцип сохранён для будущих скриптовых обёрток над `ChatSession`.)
2. **Один вызов — один процесс, никакого состояния на диске по умолчанию.**
3. **Коды выхода — часть API скриптовых обёрток.**
4. **Всё, что умеет TUI, должно быть доступно ядру.**
   Если функциональность нельзя вызвать из скрипта на `ChatSession`,
   она не считается готовой.
5. **Машиночитаемость важнее красоты.**
6. **Никаких интерактивных промптов в скриптах.**
7. **Ядро — библиотека, TUI/GUI — тонкие оболочки.** Любой сценарий должен
   быть воспроизводим 10 строками Python-скрипта на `ChatSession` (§1.4).

### 1.1. Удалено (бывший CLI-контракт, 2026-09-18)

Удалены `axiom -p`, `--json`-NDJSON, pipe-режим, `--list-models`,
`-m/-s/--think/--show-reasoning/--ollama-url` и коды `0/1/2/130`.
Причина: по решению владельца остаются только TUI (`axiom`) и GUI
(`axiom --gui`); скрипты работают напрямую через `ChatSession`.
Неизвестные флаги теперь дают exit `2` и справку.

## 3. Ядро

- [x] **Ссылки из сообщения читаются автоматически** (`agent._read_pasted_links`):
      если пользователь вставил http(s)-ссылку, агент сам вызывает `fetch_url`,
      подставляет реальный текст страницы в системный промпт (`PAGE_SYSTEM_PROMPT`)
      и публикует `search_result` с этой страницей как источником. Причина:
      `deepseek-r1:8b` возвращает `tool_calls: null` и отвечает «I cannot fetch
      live web pages» даже при переданных tools — полагаться на tool-calling
      модели нельзя (проверено живым запросом к Ollama 2026-09-18, см. тесты
      `tests/core/test_pasted_links.py`, 9 тестов).
- [x] `fetch_url` теперь предлагается модели вместе с `web_search`
      (`agent.OFFERED_TOOLS`) — раньше реестр его регистрировал, но модели он
      не передавался, из-за чего «открыть страницу» было невозможно в принципе.
- [x] Деталь статуса для `fetch_url` — сам URL, а не имя инструмента
      (в GUI/TUI видно, какую страницу читают).
- [ ] **Ограничение**: модели без рабочего tool-calling (`deepseek-r1`)
      по-прежнему не смогут вызвать `web_search` сами — им доступен только
      принудительный поиск («С поиском» в TUI / кнопка поиска в GUI) и авто-чтение
      ссылок. Рассмотреть эвристику «авто-поиск по вопросительным вопросам о
      текущих событиях» — но только с явным индикатором в UI, без тихой траты
      токенов.
- [ ] Ветка принудительного поиска (`force_search`) **заменяет** системный
      промпт целиком (`SEARCH_SYSTEM_PROMPT`), из-за чего пользовательский
      `system_prompt` теряется. В ветке чтения ссылок это уже исправлено
      (базовый промпт сохраняется, контекст добавляется) — привести поиск к
      тому же поведению (2026-09-18).
- [ ] `MultiSearchProvider` (brave/wikipedia/multi): сверить, какие
      провайдеры реально включены по умолчанию; убрать неиспользуемые пути
      конфигурации (см. §7).
- [ ] Проверить `response.text`-декодирование у провайдеров для сайтов в
      windows-1251 без charset в заголовке (httpx не читает `<meta charset>`;
      obrmos.ru отдаёт UTF-8 — проверено, но это не гарантия для других).
- [ ] Метрики `Done.tokens_in` приходят не от всех моделей — задокументировать

- [ ] История: лимит/индекс по размеру (`~/.axiom/history/` растёт бесконечно).
- [ ] `fetch_url`: лимиты на «тяжёлых» страницах (`MAX_PAGE_CHARS = 6000` уже
